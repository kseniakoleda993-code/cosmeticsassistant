# Телеграм-бот для подбора косметики

Документ описывает проект: телеграм-бот, который помогает подобрать косметику. Язык разработки — C++. Библиотеки бота пишутся внутри проекта; для тестов используется GoogleTest.

Документ является общим описанием для всей команды. Он задаёт поведение бота и состав модулей, чтобы разные участники могли работать над разными частями и не мешать друг другу.

## Назначение бота

Бот работает как помощник в магазине. Он уточняет категорию, затем конкретный товар, затем бюджет, после чего предлагает подходящую позицию с ценой. При желании подбор повторяется. В конце разговора бот показывает общую стоимость всего подобранного.

Весь диалог построен только на кнопках. Текст вручную вводить не требуется. Это уменьшает число ошибок распознавания и упрощает проверку поведения.

## Начало работы

Пользователь нажимает кнопку "Старт" (команда /start). После этого бот отправляет приветствие.

Первое сообщение: "Привет!"

Второе сообщение: "Я твой помощник по подбору косметики"

Сразу после этого отправляется третье сообщение: "Что ты хочешь выбрать?" К сообщению прикреплены кнопки. Каждая кнопка размещается отдельной строкой. Набор кнопок: "уход для волос", "уход для тела", "уходовая косметика", "декоративная косметика".

## Раздел "уход для волос"

При нажатии кнопки "уход для волос" бот отправляет сообщение "Что именно с этого раздела ты хочешь найти?" и показывает кнопки: "шампунь", "кондиционер", "маска", "масло", "термозащита", "сухой шампунь".

## Раздел "уход для тела"

При нажатии кнопки "уход для тела" бот отправляет сообщение "Что именно с этого раздела ты хочешь найти?" и показывает кнопки: "гель для душа", "скраб для тела", "крем/лосьон для тела".

## Раздел "уходовая косметика"

При нажатии кнопки "уходовая косметика" бот отправляет сообщение "Что именно с этого раздела ты хочешь найти?" и показывает кнопки: "скраб", "гель для умывания", "тонер", "энзимная пудра".

## Раздел "декоративная косметика"

При нажатии кнопки "декоративная косметика" бот отправляет сообщение "Что именно с этого раздела ты хочешь найти?" и показывает кнопки: "тональная основа", "румяна", "тушь", "помада", "гель для бровей", "консилер".

## Вопрос про бюджет

После выбора конкретного товара из любого раздела бот отправляет сообщение "Отлично, какой у тебя бюджет?" и показывает две кнопки: "средний" и "выше среднего".

Бюджет определяет, какой вариант товара будет показан. Для каждой позиции в каталоге предусмотрено два варианта: бюджетный и подороже. Выбор "средний" соответствует бюджетному варианту, выбор "выше среднего" — варианту подороже.

## Выдача результата

После выбора бюджета бот отправляет сообщение "Хорошо, вот что я подобрал:" и далее название товара и его цену.

Конкретные названия и цены на данный момент не определены и будут добавлены позже. До этого момента в каталоге используются заглушки. Для каждой позиции из всех разделов требуется найти два варианта товара: дешевле и дороже.

Сразу после показа товара его цена добавляется в корзину пользователя. Корзина нужна для подсчёта итоговой суммы в конце разговора.

## Вопрос про продолжение

После выдачи товара бот отправляет сообщение "Нужно ли подобрать что-то ещё?" и показывает две кнопки: "да" и "нет".

При нажатии "да" бот возвращается к сообщению "Что ты хочешь выбрать?" со всеми четырьмя кнопками разделов. Подбор начинается заново, при этом ранее подобранные товары сохраняются в корзине.

При нажатии "нет" бот отправляет сообщение "Отлично! Суммарная стоимость продуктов:" и далее сумму цен всех подобранных за разговор товаров. После суммы отправляется текст "Был рад помочь! Если есть какие-либо вопросы, задавай".

## Состояния пользователя

Бот общается с несколькими людьми одновременно, поэтому текущий шаг диалога хранится отдельно для каждого пользователя в виде состояния.

Предусмотрены состояния: ожидание старта, выбор раздела, выбор товара внутри раздела, выбор бюджета, вопрос про продолжение, конец разговора.

При получении нажатия кнопки бот определяет состояние этого пользователя и по состоянию выбирает дальнейшее действие. Такой подход исключает путаницу при нажатии кнопки из устаревшего сообщения.

Помимо состояния для каждого пользователя хранятся выбранный раздел, выбранный товар, выбранный бюджет и список подобранных товаров с ценами.

## Самописные библиотеки

Все части бота разрабатываются внутри проекта. Готовые библиотеки для телеграма не используются. В коде бота допускается только стандартная библиотека C++ и системные средства работы с сетью. Для тестов используется GoogleTest.

Библиотека работы с сетью. Открывает соединение с сервером телеграма, отправляет HTTP-запрос и получает ответ. Соединение должно быть защищённым, так как телеграм принимает запросы только по HTTPS.

Библиотека разбора JSON. Телеграм присылает ответы в формате JSON, из которых нужно извлекать поля: идентификатор чата, текст сообщения, данные нажатой кнопки. Также требуется обратная операция — сборка JSON для отправки сообщения с кнопками.

Библиотека работы с API телеграма. Получает новые обновления (getUpdates), отправляет сообщения (sendMessage) и прикрепляет к ним кнопки. Опирается на две предыдущие библиотеки.

Библиотека логики бота. Хранит состояния пользователей, выдаёт текст и набор кнопок для каждого шага, обрабатывает переходы между состояниями, считает сумму корзины.

Библиотека каталога товаров. Хранит разделы, позиции внутри разделов и по два варианта товара на каждую позицию. Логика бота получает из каталога название и цену по выбранной позиции и бюджету.

## Структура файлов

Проект разбивается на много небольших файлов для удобства совместной работы. Каждая библиотека располагается в отдельной папке и имеет свой заголовочный файл и файл реализации.

Отдельно выделяется главный файл программы. В нём выполняется запуск бота, чтение токена и бесконечный цикл получения и обработки обновлений.

Токен бота не хранится в исходном коде. Он читается из переменной окружения или из отдельного файла настроек, который не попадает в репозиторий.

## Обработка ошибок

Падение программы при любой внешней ошибке недопустимо. При неудачном подключении к серверу выполняется пауза и повторная попытка. При получении некорректного ответа запись попадает в лог, а само обновление пропускается. При нажатии кнопки, не соответствующей текущему состоянию, бот напоминает, какой ответ ожидается, и показывает кнопки заново.

## Тесты

Тесты пишутся на каждую библиотеку. Для разбора JSON проверяется корректное чтение полей и устойчивость к некорректным данным. Для логики бота проверяются все переходы между состояниями, включая полный путь от старта до конца и повторный подбор. Для каталога проверяется выдача нужного варианта товара по разделу, позиции и бюджету. Для подсчёта суммы проверяется правильность сложения, в том числе при нескольких подобранных товарах.

## Открытые вопросы

Требуется найти реальные названия товаров и цены, по два варианта на каждую позицию. Требуется определить валюту отображения цен и формат хранения цены. Требуется решить, сохраняется ли корзина после перезапуска программы и что происходит при возврате пользователя через длительное время.

## Сборка и проверка

Нужны CMake 3.16+ и компилятор C++17. GoogleTest 1.17.0 подключается через FetchContent с проверкой SHA-256; при первой настройке нужен интернет. Подключение соответствует [документации GoogleTest](https://google.github.io/googletest/quickstart-cmake.html).

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Пока реализуется библиотечная основа проекта; исполняемого бота ещё нет.

Реализовано:

- #2: настроен GoogleTest и обнаружение тестов через CTest. Отдельная проверка подтверждает ненулевой код при падении, диагностику и продолжение остальных тестов.
- #3: `Result<T>` со значением или ошибкой; неверный доступ вызывает `std::logic_error`.
- #4: чтение токена из `TELEGRAM_BOT_TOKEN`, затем из `.bot-token`. Файл содержит только токен в одной строке; пустая переменная считается отсутствующей. Ошибки не содержат токен. Файл исключён из Git.
- #5: абстрактный `Transport` и `FakeTransport` с заданным ответом или ошибкой и историей запросов без обращения к сети.
- #6: разбор отдельного HTTP/1.0 или HTTP/1.1 ответа: статус, заголовки в нижнем регистре и тело по `Content-Length`. Обрезанные ответы, неверные и повторные длины отклоняются. `Transfer-Encoding` и ответы с непустым телом без длины пока не поддерживаются.
- #17: четыре раздела каталога с преобразованием в точные тексты кнопок и обратно. Неизвестные тексты возвращают ошибку.
- #18: девятнадцать позиций каталога, уникальные тексты кнопок и обратное преобразование.
- #19: позиции распределены по четырём разделам в порядке кнопок из описания; все девятнадцать встречаются ровно один раз.
- #20: бюджеты «средний» и «выше среднего» с преобразованием в текст кнопки и обратно.
